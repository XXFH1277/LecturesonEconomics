## 第一大板块：理论基础

### 本课从哪个零基础问题开始

上一课从芯片供应商的收入、库存和风险因素出发。今天转到购买芯片、建设数据中心的云厂商，先问：

```text
公司说“今年投入很多钱建设 AI 基础设施”，
我应该在财报哪几行看到它？
```

答案不是只看一个 CapEx 数字。至少要顺着这条链阅读：

```text
建设承诺
-> 购买或租赁土地、建筑、服务器和网络设备
-> 形成 PPE additions 或租赁资产
-> 资产达到可使用状态
-> 开始计提折旧
-> 形成可出售的云计算容量
-> 客户签约形成 RPO 或 backlog
-> 履约后确认云收入
-> 扣除运营成本和资本开支后观察现金回报
```

### 先分清五种容易混淆的数字

| 指标 | 回答的问题 | 为什么可能不同 |
| --- | --- | --- |
| Capital Expenditures | 本期资本性投入有多大 | 公司定义可能包含融资租赁，也可能只按现金口径 |
| PPE Additions | 本期新增了多少不动产、厂房和设备 | 可能包含尚未付款、融资租赁等非现金增加 |
| Cash Paid for PPE | 本期实际为 PPE 支付多少现金 | 受付款时点和应付账款影响 |
| Lease Commitments | 已签约但未来才付款或启用的租赁有多少 | 不一定立即进入当期 CapEx |
| Depreciation | 已投入使用资产在本期分摊了多少成本 | 取决于启用时点、使用寿命和资产结构 |

最小会计直觉是：

```text
PPE additions ≠ 当期现金流出
CapEx ≠ 所有未来数据中心承诺
折旧 ≠ 当期购买设备花掉的现金
RPO ≠ 当期收入
收入增长 ≠ 已经收回全部投资
```

### 什么是 PPE

PPE 是 Property, Plant and Equipment，中文常译为“不动产、厂房和设备”。云厂商的 PPE 常包括：

- 土地和数据中心建筑；
- 服务器、CPU、GPU 和网络设备；
- 冷却、供电和配套设施；
- 租赁改良和内部使用软件；
- 尚未达到可使用状态的在建资产。

PPE 是资产负债表项目。购买 PPE 的现金通常出现在现金流量表的投资活动中；资产投入使用后，成本再通过折旧逐期进入利润表。

### 为什么折旧会晚于资本开支

数据中心不是付款后立即产生收入。土地、建筑、供电、网络和服务器需要建设、安装、测试。只有资产“达到预定可使用状态”后才开始折旧。

因此扩张初期可能出现：

```text
资本开支先大幅增加
-> 在建资产增加
-> 可用容量随后增加
-> 折旧再逐步上升
-> 收入和毛利率是否覆盖折旧，需要更晚验证
```

这也是为什么只比较同一个季度的 CapEx 和云收入，容易得出错误结论。

### 什么是 RPO

RPO 是 Remaining Performance Obligations，中文可理解为“剩余履约义务”。它代表已签合同中尚未确认收入的部分。

```text
签约承诺 -> RPO / backlog
实际提供云服务 -> 确认收入
客户付款时点 -> 现金流
```

三者时间可能不同。RPO 很大，说明合同覆盖度可能较高，但不能直接等同于下一季度收入，因为合同期限、取消条款、客户集中和履约速度都可能不同。

### 怎样初步观察 AI 投资回报

零基础阶段先不急着算复杂 IRR，可以用四层检查：

1. 需求层：云收入增速、RPO/backlog、客户使用量是否增长。
2. 容量层：新增资产是否投入使用，管理层是否仍说供不应求。
3. 利润层：云业务营业利润、云毛利率、折旧是否恶化或改善。
4. 现金层：经营现金流能否覆盖现金资本开支，自由现金流怎样变化。

这四层要一起看。只看到强劲订单，无法证明回报已经实现；只看到自由现金流下降，也不能直接证明投资失败，因为项目可能仍在建设期。

### 常见误区

- 误区一：把所有公司披露的 CapEx 当成同一口径。租赁和非现金增加会造成差异。
- 误区二：把 RPO 当成已赚到的收入。它仍需履约并按会计规则确认。
- 误区三：资本开支上升就一定是坏事。关键是未来容量、收入、利润和现金回报。
- 误区四：云收入增长就证明 AI 项目回本。收入还要覆盖折旧、能源、维护、融资和运营成本。
- 误区五：折旧是“假成本”。折旧对应真实资产消耗和更新需求，不能忽略。
- 误区六：把 operating lease 不计入 CapEx 理解为没有投入。会计分类变化不等于物理基础设施消失。

## 第二大板块：实时背景与市场传导

### Microsoft：一个数字背后有三种口径

Microsoft FY2026 Q4 earnings call 披露：

- 当季资本开支为 410 亿美元；
- 约三分之二用于短寿命资产，主要是 CPU 和 GPU；
- 其余用于长寿命资产；
- 融资租赁为 56 亿美元，主要是大型数据中心场地；
- 现金支付 PPE 为 358 亿美元；
- Microsoft Cloud 收入为 593 亿美元，同比增长 27%；
- 商业 RPO 为 6,780 亿美元，同比增长 84%；剔除 OpenAI 后增长 25%；
- Microsoft Cloud 毛利率为 65%，同比下降，管理层归因包括销售组合、AI 基础设施投入和产品使用量增加。

这组数字说明：

```text
410 亿美元 CapEx
不等于
358 亿美元现金 PPE 支出
```

差额的一部分来自融资租赁等口径。FY2026 10-K 进一步显示，全年 PPE 原值为 4,317.67 亿美元，服务器、网络设备和软件为 2,158.74 亿美元；全年折旧费用为 343 亿美元，服务器和网络设备的一般估计使用寿命为 2 至 6 年。

电话会还解释，未来部分数据中心租赁可能从融资租赁转为经营租赁。经营租赁不计入公司所说的 CapEx，因此 CY2026 CapEx 预期调整至约 1,750 亿美元，但管理层同时表示，剔除租赁分类影响后，基础设施投资预期没有改变。

这是本课最重要的口径案例：

```text
会计分类变化
可以改变 CapEx 指标，
却不一定改变真实建设计划。
```

### Alphabet：先看“尚未投入使用”的资产

Alphabet Q2 2026 10-Q 披露：

- Q2 资本开支为 449 亿美元，主要反映技术基础设施投资；
- 2026 年上半年资本开支为 806 亿美元，2025 年同期为 396 亿美元；
- 上半年 PPE 折旧为 135.86 亿美元；
- 截至 2026-06-30，尚未投入使用的资产为 1,228.14 亿美元；
- 尚未开始的租赁未来付款为 852 亿美元，主要与数据中心有关；
- Google Cloud Q2 收入为 248 亿美元，同比增长 82%；
- 总剩余履约义务为 5,195 亿美元，其中 5,139 亿美元与 Google Cloud 有关。

尚未投入使用的资产很关键。它说明大量资金已经进入建设链条，但相关资产尚未开始折旧，也未必已经形成完整可售容量。分析者需要继续追踪：这些资产何时转为在用、折旧何时上升、云收入和利润能否同步增长。

### Amazon：现金资本开支与 AWS 分部新增资产

Amazon Q2 2026 10-Q 披露：

- Q2 现金资本开支为 531 亿美元，主要用于技术基础设施和履约网络，其中大部分技术基础设施投资支持 AWS 增长；
- Q2 AWS 净新增 PPE 为 486.04 亿美元，2026 年上半年为 901.20 亿美元；
- AWS Q2 销售额为 422 亿美元，同比增长 37%；
- AWS Q2 营业利润为 166 亿美元；
- 截至 2026-06-30 的十二个月经营现金流为 1,614.03 亿美元；
- 同期扣除净 PPE 购买后的公司定义自由现金流为负 76.04 亿美元。

Amazon 同时提醒，自由现金流是补充指标，不代表可任意支配的全部剩余现金。它还会受到收购、融资安排和资本开支付款时点影响。

### 三家公司放在一起怎样读

| 公司 | 最新云需求信号 | 最新投资信号 | 需要继续观察 |
| --- | --- | --- | --- |
| Microsoft | Cloud 收入 593 亿美元；商业 RPO 6,780 亿美元 | Q4 CapEx 410 亿美元；现金 PPE 358 亿美元 | RPO 转收入、毛利率、租赁分类、折旧 |
| Alphabet | Cloud 收入 248 亿美元；Cloud backlog 5,139 亿美元 | Q2 CapEx 449 亿美元；未投入使用资产 1,228.14 亿美元 | 资产启用、折旧、云利润和融资成本 |
| Amazon | AWS 收入 422 亿美元；同比增长 37% | Q2 现金 CapEx 531 亿美元；AWS 净新增 PPE 486.04 亿美元 | AWS 利润、公司自由现金流、资产利用率 |

不能直接用表中数字做“谁更好”的排名，因为三家公司披露定义、业务组合和租赁结构不同。正确用途是建立各自的连续时间序列，再观察同一公司口径下的变化。

## 政治、制度和规则视角

### 制度怎样影响这些数字

- SEC 披露制度要求公开公司在 10-K、10-Q 和相关业绩材料中披露财务报表、会计政策、重大承诺和风险。
- Topic 606 等收入确认规则决定合同承诺何时成为收入，RPO 不能提前全部入账。
- 租赁会计决定融资租赁和经营租赁如何进入资产负债表、现金流量表和公司 CapEx 指标。
- 资产使用寿命估计会改变每期折旧；使用寿命延长可能降低当期折旧，但不代表服务器物理性能自动提高。
- 数据中心还受土地、电力、能源合同、网络、环境许可、出口管制和融资条件约束。

### 已确认事实

- Microsoft FY2026 Q4 披露 CapEx、融资租赁、现金 PPE、云收入、RPO 和云毛利率，并明确说明租赁分类变化会影响 CapEx 指标。
- Microsoft FY2026 10-K 披露 PPE 构成、折旧费用和服务器及网络设备使用寿命范围。
- Alphabet Q2 2026 10-Q 披露资本开支、折旧、尚未投入使用资产、未来数据中心租赁付款和 Cloud backlog。
- Amazon Q2 2026 10-Q 披露现金资本开支、AWS 净新增 PPE、AWS 分部收入利润和自由现金流调节表。

### 分析推理

- 三家公司同时扩大 AI 基础设施，说明云厂商正在为预期需求提前建设容量。
- RPO/backlog 和云收入快速增长，为投资需求提供了支持，但仍不能单独证明项目回报率。
- 未投入使用资产、租赁承诺和短寿命服务器占比提高，意味着未来折旧、运营成本和更新资本开支可能继续上升。

以上是基于官方披露的教学推理，不是公司给出的收益保证，也不构成投资建议。

### 仍需观察

- 新增容量何时投入使用，供不应求的表述是否缓解。
- RPO/backlog 中多长时间可以转为收入，是否高度集中于少数客户。
- 云毛利率和营业利润能否吸收折旧、能源和维护成本。
- 经营租赁增加后，只看 CapEx 是否会低估长期支付承诺。
- FY2027 后续季度是否出现投资计划、使用寿命或客户需求变化。

## 关键词词典

| 关键词 | 中文翻译 | 白话解释 | 为什么重要 |
| --- | --- | --- | --- |
| Capital Expenditures | 资本开支 | 为长期资产投入的资金 | 观察扩产强度 |
| PPE Additions | PPE 增加 | 新增土地、建筑和设备 | 不一定等于当期现金支出 |
| Cash Paid for PPE | PPE 现金支付 | 本期实际付出的购置现金 | 直接影响投资现金流 |
| Finance Lease | 融资租赁 | 经济效果更接近融资购买资产的租赁 | 可能计入公司 CapEx |
| Operating Lease | 经营租赁 | 按经营租赁方式确认的使用权安排 | 可能不计入公司 CapEx，但仍有付款义务 |
| Depreciation | 折旧 | 将资产成本分摊到使用期间 | 影响利润和毛利率 |
| Assets Not Yet in Service | 尚未投入使用资产 | 仍在建设或安装、尚不能使用的资产 | 通常还未开始折旧 |
| RPO | 剩余履约义务 | 已签合同中尚未确认收入的部分 | 是需求覆盖信号，不是当期收入 |
| Capacity Constraint | 容量约束 | 客户需求超过可提供计算能力 | 解释为何先投资再确认收入 |
| AI Monetization | AI 商业化变现 | 把 AI 使用量转为收入、利润和现金流 | 判断投资回报的最终环节 |

## 案例练习

假设一家云厂商本季披露：

```text
CapEx：400 亿美元
Cash Paid for PPE：340 亿美元
融资租赁：60 亿美元
RPO：6,000 亿美元
云收入：550 亿美元
```

请先回答：

1. 为什么不能说公司本季现金支出了 400 亿美元购买 PPE？
2. 为什么 6,000 亿美元 RPO 不能直接算作本季收入？
3. 下一季应继续检查哪三个指标，才能观察投资是否开始转化为回报？

参考思路：CapEx 可能包含融资租赁；RPO 需要未来履约；后续要看资产启用、折旧、云收入/利润和现金流。

## 结论边界

### 本课可以得出的结论

- 研究云厂商 AI 投资，必须分清现金资本开支、PPE 增加、租赁、折旧和订单储备。
- Microsoft、Alphabet 和 Amazon 的最新官方披露都显示 AI/云基础设施投入处于高位，同时云需求指标也在增长。
- 判断回报需要跨期追踪容量、收入、利润和现金流，不能只看单一季度。

### 本课不能得出的结论

- 不能据此断言任何一家公司的 AI 投资一定成功或失败。
- 不能直接横向比较不同公司口径的 CapEx 后得出效率排名。
- 不能把 RPO、backlog、云收入或股价变化当成完整投资回报率。
- 本课不构成具体证券买卖建议。
