# 第一百零一课：AI 基础设施季度复查工作台入门：指标树、来源日志、变动解释、阈值和无行动结论

## 基本信息

- 日期：2026-09-09。
- 核验截至：2026-09-09；NVIDIA 数据主要截至 2026-07-26，Microsoft 与 Alphabet 数据主要截至 2026-06-30。
- 主题：怎样把研究备忘录变成每季度可以重复更新的工作台。
- 学习目标：建立指标树、来源日志和复查规则，区分正常波动、口径断点与真正改变判断的事件。
- 适用范围：AI 基础设施公司与相关基金的学习型跟踪；不构成自动交易系统或投资建议。
- 核心来源：NVIDIA、Microsoft、Alphabet 官方财报和 SEC 非 GAAP 指引。

## 第一大板块：理论基础

### 1. 工作台解决什么问题？

季度研究最容易出现两个错误：每次都从头搜资料，或者只把新数字覆盖旧数字。前者浪费时间，后者丢失口径和解释。

一个最小工作台只需要五张表：

| 表 | 记录内容 | 目的 |
| --- | --- | --- |
| 指标树 | 需求、供给、运营、利润、现金、风险 | 保持因果顺序 |
| 来源日志 | 链接、发布日期、报告期、页码或章节 | 让数字可追溯 |
| 变动表 | 本期、上期、同比、口径说明 | 识别真正变化 |
| 触发器 | 基线、阈值、触发后的动作 | 防止临时改规则 |
| 决策日志 | 判断是否改变、为什么、下次看什么 | 保存思考过程 |

工作台可以是 Markdown、电子表格或网页。关键不是技术形式，而是字段固定、来源可核对、历史不被覆盖。

### 2. 指标树：领先、同步与滞后

Metric Tree，指标树，是把多个指标按因果关系组织起来。

```text
领先指标：RPO、采购承诺、资本开支计划、容量建设
同步指标：出货、收入、用量、投运容量、毛利率
滞后指标：折旧、经营现金流、自由现金流、减值、回报率
```

Leading Indicator，领先指标，可能先于结果变化，但容易受取消、延期和口径影响。Lagging Indicator，滞后指标，确认度较高，却可能在问题发生后才显现。研究不能只选一种。

### 3. 每个数字必须带身份标签

至少记录以下字段：

```text
公司 | 指标 | 数值 | 单位 | 报告期 | 截止日
披露/计算/推断 | 原始来源 | 定义 | 可比性说明 | 更新时间
```

- Reported，披露值：公司或监管文件直接给出。
- Calculated，计算值：由披露值经过透明算式得到。
- Inferred，推断值：根据多个信号判断，不能伪装成精确事实。

例如“72,965 + 2,747 = 75,712 百万美元”属于计算值；“新增容量可能提高未来收入”属于推断。

### 4. Baseline、Threshold 和 Trigger 不相同

Baseline，基线，是当前正常状态或比较起点。Threshold，阈值，是事先设定的观察边界。Trigger，触发器，是越过阈值后执行的研究动作。

```text
基线：连续三季同口径毛利率区间
阈值：毛利率低于区间下沿，且公司解释不能由产品转换完全说明
触发器：重读成本、库存和定价披露，更新压力情景
```

阈值不是自动买卖价格。零基础阶段更适合使用“方向 + 连续期数 + 原因确认”，避免用缺乏统计基础的小数点制造精确感。

### 5. 变动解释要过四道检查

1. **期间**：季度、半年、全年还是滚动十二个月？
2. **范围**：集团、分部、产品还是单一地区？
3. **定义**：公司是否修改指标或纳入新合同？
4. **机制**：变化来自数量、价格、组合、汇率、并购还是会计分类？

只有四道检查通过后，才能解释趋势。同比增长率看似可比，也可能因收购、处置或定义变化失真。

### 6. Version Break：口径断点要单独保存

Version Break，版本断点，是指标定义、统计范围或计算方式改变，使新旧数据不能直接比较。处理方式不是删除旧数据，而是：

```text
保留原序列
+ 标记断点日期
+ 记录新旧定义
+ 公司提供重述值时另建可比序列
+ 没有重述值时停止计算跨断点增速
```

Alphabet 2026 年第一季度将期限不超过一年的合同纳入 RPO，就是本课的真实口径断点。[S5]

### 7. No-action Decision 也是结果

No-action Decision，无行动结论，是数据更新后判断没有达到修改条件，因此记录“保持原判断”，并说明依据。

合格记录应写：本期新增了什么证据；它支持、削弱还是不影响原判断；为什么没有触发重写；下一次复查什么。不能只写“继续观察”。

## 第二大板块：实时背景与市场传导

### NVIDIA：用供应商指标树复查

| 层级 | 最新已确认事实 | 工作台标签 |
| --- | --- | --- |
| 需求/销售 | FY2027 Q2 数据中心收入 890 亿美元，同比增长 117% | 披露值、季度、分部 |
| 盈利 | GAAP 与非 GAAP 毛利率均为 75.0% | 披露值、季度、合并 |
| 供给准备 | 库存 315.75 亿美元，2026-01-25 为 214.03 亿美元 | 披露值、时点 |
| 承诺风险 | 供应与产能承诺约 2,790 亿美元 | 披露值、时点 |
| 质量风险 | 当季库存相关准备 7.84 亿美元 | 披露值、期间 |

来源为 NVIDIA 业绩公告与 10-Q。[S1][S2] 这些指标应并列，不应把高收入覆盖库存和承诺风险。

分析推理：若未来收入、毛利率和库存周转共同保持健康，供应扩张更可能被需求吸收；若库存、准备和承诺继续上升，而收入转化放慢，资本循环风险提高。

仍需观察：公司没有公开足够数据让外部研究者计算新架构项目级利用率和回报率。

### Microsoft：需求、交付和现金三栏分开

| 栏目 | 最新已确认事实 | 不能直接推出 |
| --- | --- | --- |
| 需求 | 商业 RPO 6,780 亿美元；剔除 OpenAI 后增长 25% | 全部属于 Azure AI |
| 交付 | Q4 新增 31 个数据中心、约 1 GW 容量 | 所有容量已经满负荷 |
| 业务 | FY2026 Azure 收入超过 1,000 亿美元，增长 41% | 增量利润率与收入增速相同 |
| 现金 | Q4 经营现金流 554 亿美元，FCF 196 亿美元 | 资本开支已完成回收 |

这些数据来自官方电话会和指标页。[S3][S4] Microsoft 同时披露商业 RPO 加权平均期限为 2.3 年，约 30%预计未来 12 个月确认。期限信息应与总额一起显示。

分析推理：工作台若只显示 RPO 总额，会隐藏客户集中和确认时间；若只显示 FCF，会忽略当前建设为未来容量服务。三栏共同变化才更接近投资回报过程。

### Alphabet：把定义变化显示在图表旁

Alphabet Q2 2026 10-Q 披露总 RPO 5,195 亿美元，其中 Google Cloud 5,139 亿美元；略高于一半预计在未来 24 个月确认。公司同时说明，2026 年第一季度起纳入期限不超过一年的合同。[S5]

工作台应在 2026 Q1 位置画出“定义变化”标记。若没有公司重述的旧口径数据，不计算跨断点的长期增长率。Q2 Google Cloud 收入为 248 亿美元、同比增长 82%，可以作为同期业务指标，但不能用它倒推出所有 RPO 的平均价格或利润率。[S6]

### 一个可执行的季度更新顺序

```text
1. 锁定报告期和文件版本
2. 从 10-Q/10-K 更新原始值
3. 用官方业绩材料补管理层解释
4. 标记定义、范围和会计变化
5. 重算计算值并保留公式
6. 对照基线、阈值和反证
7. 记录“修改判断”或“无行动”
8. 写明下一次数据来源和复查时间
```

## 政治、制度和规则视角

工作台不仅跟踪公司数字，还要保存制度版本。出口许可、数据中心并网规则、能源费率和披露规范改变时，必须记录发布机构、生效日期、适用对象和过渡安排。

SEC 对非 GAAP 指标的解释指出，自由现金流没有统一定义，公司使用时要说明计算并与 GAAP 指标调节，也不能暗示这笔现金可不受限制地任意支出。[S7] 因此工作台要把“公司定义 FCF”和“教学补充现金观察值”分成不同字段。

规则变化与公司受影响之间仍有距离。尚未生效的提案、管理层风险提示和已经确认的财务影响，应使用不同状态标签。

## 关键词词典

| 关键词 | 中文与白话解释 | 用途 |
| --- | --- | --- |
| Metric Tree | 指标树；按因果关系排列指标 | 防止只盯一个数字 |
| Leading Indicator | 领先指标；可能先于结果变化 | 提前发现需求或投入变化 |
| Lagging Indicator | 滞后指标；结果发生后确认 | 核验利润和现金回报 |
| Data Provenance | 数据来源链；数字从哪里来、怎样算 | 便于复核和纠错 |
| Baseline | 基线；当前比较起点 | 判断变化是否异常 |
| Threshold | 阈值；预先设定的观察边界 | 减少事后改规则 |
| Trigger | 触发器；越过边界后的研究动作 | 决定何时重读和重算 |
| Version Break | 版本断点；定义变化导致不可直接比较 | 防止制造虚假趋势 |
| No-action Decision | 无行动结论；证据不足以改判断 | 保存研究纪律 |

## 回顾提示

- 第 100 课建立“一页备忘录”，本课建立“多季度历史”。
- 备忘录回答当前怎么看，工作台回答判断何时以及为什么改变。
- 图表美观不能替代来源、定义和报告期。
- 阈值触发的是复查动作，不是自动交易。

## 案例拆解

### 示例：NVIDIA 季度复查卡

**原判断**：当前需求强，但供应扩张提高未来执行风险。

**本期新增证据**：数据中心收入和毛利率维持强劲；库存、库存准备和供应承诺同步增加。[S1][S2]

**基线**：保存过去四个季度同口径收入、毛利率、库存、准备和承诺；不把资产负债表时点值与季度流量直接求增长率后混用。

**触发器**：若收入转化放缓与库存风险指标恶化连续出现，重做需求和供应压力情景；单项一次波动只标记观察。

**当前结论**：新增证据同时支持需求强与风险扩张，尚不能仅凭一个方向重写判断，记录无行动。

**下次复查**：下一份 10-Q 的收入、毛利率、库存、库存准备、供应承诺及客户采购延迟风险表述。

## 个人情境连接

零基础学习者可以先用 Markdown 表格：每家公司每季度新增一行，不覆盖历史。图表只画三到五个最关键指标，并在口径变化点加注释。

如果未来把工作台做成网页，页面应直接读取这些结构化字段，而不是手工复制数字。这样课程文档、来源日志和可视化不会出现多个互相冲突的版本。

个人持仓复查还需加入基金权重、买入目的、时间范围、税务和风险承受能力；本课的公司指标树不能替代个人财务规划。

## 结论边界

1. 工作台提高一致性，不会消除数据滞后、披露不足和管理层估计误差。
2. 阈值需要随样本积累校准，本课不提供自动买卖信号。
3. 公司间指标名称相同也可能定义不同，必须先核对范围和期间。
4. RPO、资本开支和收入都不能单独证明项目回报率。
5. “无行动”只表示当前证据未达到预设复查条件，不表示风险为零。
