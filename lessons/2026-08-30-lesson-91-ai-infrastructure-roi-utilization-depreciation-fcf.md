## 第一大板块：理论基础

### 本课从哪个零基础问题开始

上一课知道了钱怎么进入数据中心和服务器。今天继续问：

```text
什么时候可以说这些 AI 基础设施“开始产生回报”？
```

不能只等公司说“需求很强”，也不能只看一季自由现金流。回报要按时间顺序验证：

```text
资本投入
-> 资产建成并投入使用
-> 可售容量增加
-> 客户开始使用
-> 收入爬坡
-> 收入覆盖电力、人员、维护和折旧
-> 形成营业利润
-> 经营现金流覆盖持续资本开支
-> 经过若干期后收回初始投入
```

### 回报复查的五层框架

#### 第一层：资产是否启用

检查：

- 尚未投入使用资产是否转为在用资产；
- 数据中心建设和租赁何时开始；
- 折旧是否随资产启用上升；
- 管理层是否仍称容量受限。

如果资本开支很高，但尚未投入使用资产继续快速累积，收入回报可能仍在后面。

#### 第二层：容量是否被客户使用

容量利用率是已用计算资源占可用资源的比例。云厂商通常不完整披露统一的 AI 利用率，因此只能使用替代信号：

- 云收入和使用量增长；
- RPO/backlog 转化；
- 管理层关于供不应求或新增容量快速售出的表述；
- 单位成本、毛利率和效率变化；
- 客户集中和合同期限。

替代信号不是精确利用率。必须标注为分析推理，不能冒充已披露事实。

#### 第三层：收入能否覆盖折旧和运营成本

数据中心回报不是“收入减资本开支”这么简单。利润表大致经历：

```text
云收入
- 电力、网络、维护、人员等运营成本
- 服务器和建筑折旧
= 云业务利润的一部分
```

资本开支先进入资产负债表，之后通过折旧进入利润表。短寿命 GPU/CPU 占比高时，未来几年折旧压力可能更快体现。

#### 第四层：现金是否回流

最简自由现金流公式是：

```text
自由现金流 ≈ 经营现金流 - 现金资本开支
```

但不同公司定义可能不同。租赁付款、资产出售奖励、收购和营运资本会改变结果。自由现金流下降可能表示投资期提前支出，也可能表示回报不足，需要结合收入和利润判断。

#### 第五层：回报是否足以补偿风险

最简回收期可以写成：

```text
回收期 ≈ 初始投入 / 每年新增经营现金流
```

例子：投入 100 亿元，每年新增经营现金流 20 亿元，静态回收期约 5 年。

这个公式忽略折现、维护资本开支、税、残值、利用率变化和技术淘汰，只适合入门。更正式的分析要用增量自由现金流、NPV、IRR 或 ROIC，并采用多种情景。

### 为什么要看“增量”而不是总量

云厂商本身还有办公软件、广告、电商和其他业务。总公司收入或现金流上涨，不能证明新增 AI 数据中心本身回报良好。

理想指标是：

```text
新增 AI 基础设施投入
对应的新增云收入
对应的新增云利润
对应的新增经营现金流
```

现实中公司通常不会完整披露这组配对数据。因此课程采用“证据等级”：

| 等级 | 证据 | 可支持的结论 |
| --- | --- | --- |
| A | 公司直接披露 AI 收入、利润和现金回报 | 可较直接观察项目回报 |
| B | 分部收入、分部利润、CapEx、折旧 | 可观察分部层面的方向 |
| C | RPO、使用量、容量受限、管理层表述 | 只能作为需求和利用率替代信号 |
| D | 股价、媒体叙事、单一客户案例 | 只能作为线索，不能单独证明回报 |

### 常见误区

- 误区一：云收入增长率高，就等于新增资本回报率高。还要看投入规模、折旧和利润。
- 误区二：自由现金流为负，就等于投资失败。建设期现金流可能先于收入。
- 误区三：供不应求永远是好事。长期容量不足也可能让客户转向竞争对手。
- 误区四：延长服务器使用寿命会创造现金。它主要改变会计折旧节奏，不直接增加现金。
- 误区五：RPO 越大越安全。合同期限、客户集中、履约条件和取消条款都重要。
- 误区六：只看绝对 CapEx。必须与云收入、经营现金流和资产启用进度配对。

## 第二大板块：实时背景与市场传导

### Microsoft：需求强，但毛利率和折旧也要复查

Microsoft FY2026 Q4 的证据链是：

```text
商业 RPO 6,780 亿美元
-> Microsoft Cloud 当季收入 593 亿美元
-> Azure 及其他云服务收入同比增长 43%
-> 当季 CapEx 410 亿美元
-> 现金 PPE 支出 358 亿美元
-> Microsoft Cloud 毛利率 65%，同比下降
-> 当季自由现金流 196 亿美元
```

管理层表示需求仍超过可用容量，并称新增容量可以快速变现。这是容量利用率的正面替代信号，但不是精确利用率数据。

同时，FY2026 10-K 显示全年折旧费用由 FY2025 的 220 亿美元升至 343 亿美元；服务器、网络设备和软件原值大幅增加。因而后续复查不能只问 Azure 是否增长，还要问：

- 云毛利率是否稳定；
- 折旧增速是否快于云收入；
- 自由现金流是否在高投资后恢复；
- RPO 中约 30% 预计未来 12 个月确认的部分是否兑现；
- 租赁分类变化后，长期支付义务是否被低估。

### Alphabet：大量资产尚未启用，回报观察要允许时间差

Alphabet Q2 2026 的证据链是：

```text
Google Cloud backlog 5,139 亿美元
-> Q2 Cloud 收入 248 亿美元，同比增长 82%
-> Q2 CapEx 449 亿美元
-> 上半年 CapEx 806 亿美元
-> 上半年 PPE 折旧 135.86 亿美元
-> 尚未投入使用资产 1,228.14 亿美元
```

由于尚未投入使用资产规模很大，不能要求这些投入在同一季度全部反映为收入。更合理的复查顺序是：

```text
在建资产下降或增速放缓
-> 在用技术基础设施增加
-> 折旧上升
-> Cloud 收入与营业利润继续增长
-> 经营现金流逐步覆盖投资
```

如果资产启用后收入和利润没有相应改善，才是更强的反证。反之，仅仅 CapEx 高并不足以判定低回报。

### Amazon：AWS 利润强，但公司自由现金流承压

Amazon Q2 2026 的证据链是：

```text
AWS Q2 销售额 422 亿美元，同比增长 37%
-> AWS Q2 营业利润 166 亿美元
-> AWS Q2 净新增 PPE 486.04 亿美元
-> 公司 Q2 现金 CapEx 531 亿美元
-> 过去十二个月经营现金流 1,614.03 亿美元
-> 公司定义自由现金流为负 76.04 亿美元
```

这组数据同时提供两个事实：AWS 分部收入和利润在增长；全公司高资本开支压低了自由现金流。不能只选其中一个讲故事。

后续需要观察 AWS 利润增长是否能持续覆盖新增折旧和资本需求，以及电商履约网络等非 AWS 投资对公司现金流的影响。

### 一张可重复使用的回报复查表

| 层级 | Microsoft | Alphabet | Amazon | 结论边界 |
| --- | --- | --- | --- | --- |
| 投资 | Q4 CapEx 410 亿美元 | Q2 CapEx 449 亿美元 | Q2 现金 CapEx 531 亿美元 | 定义不同，不直接排名 |
| 待启用容量 | 未单列统一指标 | 未投入使用资产 1,228.14 亿美元 | 分部新增 PPE 可见，启用进度未完整单列 | 只能追踪替代信号 |
| 需求 | Cloud 收入、RPO、容量受限表述 | Cloud 收入、Cloud backlog | AWS 收入和使用量说明 | RPO/backlog 不是收入 |
| 利润 | Cloud 毛利率 | Cloud 营业利润需连续复查 | AWS 营业利润 | 分部定义不同 |
| 现金 | 经营现金流、自由现金流 | 经营现金流减 PPE 购买 | 公司 FCF 调节表 | 受付款和租赁口径影响 |

### 市场可能怎样传导

市场通常会把以下变化连在一起定价：

```text
RPO/backlog 和云收入加速
-> 预期未来容量利用率提高
-> 预期利润和现金流改善
-> 可能支持更高估值
```

但若出现：

```text
资本开支继续加速
+ 折旧快速上升
+ 云毛利率下降
+ 自由现金流持续恶化
+ 客户合同兑现放慢
```

市场可能下调对回报周期和估值的判断。这里描述的是传导机制，不是对股价方向的预测。

## 政治、制度和规则视角

### 为什么回报不只由技术决定

- 电力价格、并网速度和能源合同会影响数据中心成本与建设周期。
- 利率和融资市场会改变租赁、债务和资本成本。
- 出口管制可能限制 GPU、云服务或特定地区客户的可用范围。
- 隐私、数据跨境和 AI 监管会影响客户部署位置和合规成本。
- SEC 会计披露和公司自定义非 GAAP 指标决定外部投资者能看到多少增量回报信息。

### 已确认事实

- Microsoft 最新官方材料同时显示强劲云需求、高资本开支、上升折旧和云毛利率压力。
- Alphabet 最新 10-Q 显示资本开支、尚未投入使用资产、未来数据中心租赁和 Cloud backlog 都处于较大规模。
- Amazon 最新 10-Q 显示 AWS 收入利润增长，同时全公司自由现金流因大额 PPE 购买转负。

### 分析推理

- 当前三家公司都处于“需求验证与重资本建设并存”的阶段。
- Microsoft 的容量受限表述、Alphabet 的 Cloud backlog、Amazon 的 AWS 增长都支持需求仍强，但不能替代项目级 ROIC。
- 折旧和自由现金流是下一阶段的重要反证指标，因为它们会揭示基础设施成本是否被收入和利润吸收。

### 仍需观察

- FY2027 后续季度云收入、分部利润、折旧和自由现金流的同向或背离。
- 资产投入使用后，是否出现利用率不足或价格竞争。
- 大客户承诺是否转化为收入和现金回款。
- 服务器使用寿命、租赁分类和非 GAAP 定义是否再次变化。
- 数据中心电力、土地、网络、冷却和芯片交付是否继续形成建设瓶颈。

## 关键词词典

| 关键词 | 中文翻译 | 白话解释 | 为什么重要 |
| --- | --- | --- | --- |
| Capacity Utilization | 容量利用率 | 可用算力中实际被使用的比例 | 决定资产是否闲置 |
| Revenue Ramp | 收入爬坡 | 新容量投入后收入逐步增加 | 回报通常不会立即满载 |
| Depreciation Burden | 折旧负担 | 新资产投入使用后增加的期间成本 | 影响毛利率和营业利润 |
| Gross Margin | 毛利率 | 收入扣除直接成本后的比例 | 观察基础设施成本能否被吸收 |
| Operating Margin | 营业利润率 | 扣除营业成本和费用后的利润比例 | 比收入增长更接近经营回报 |
| Free Cash Flow | 自由现金流 | 经营现金流扣除资本开支后的补充指标 | 观察投资后的现金余量 |
| Payback Period | 回收期 | 用新增现金流收回初始投入需要多久 | 提供时间维度 |
| Incremental Return | 增量回报 | 新投入带来的新增利润或现金流 | 避免用总公司增长代替项目回报 |
| Proxy Signal | 替代信号 | 不能直接观察时使用的间接指标 | 必须标明推理边界 |
| Review Trigger | 复查触发器 | 到某日期或出现某事实时重新核验 | 防止结论停留在旧数据 |

## 案例练习

某云厂商连续两年披露：

| 指标 | 第一年 | 第二年 |
| --- | ---: | ---: |
| 云收入 | 1,000 亿元 | 1,400 亿元 |
| 云营业利润 | 250 亿元 | 300 亿元 |
| 现金资本开支 | 300 亿元 | 600 亿元 |
| 折旧 | 120 亿元 | 220 亿元 |
| 经营现金流 | 500 亿元 | 650 亿元 |

请判断：

1. 云收入和营业利润是否增长？
2. 营业利润率从多少变到多少？
3. 简化自由现金流从多少变到多少？
4. 能否仅凭第二年自由现金流下降断言投资失败？为什么？

参考思路：营业利润率由 25% 降至约 21.4%；简化自由现金流由 200 亿元变为 50 亿元。现金回报承压是事实，但项目仍可能处于建设和爬坡期，需要继续看资产启用、收入、利润和后续现金流。

## 结论边界

### 本课可以得出的结论

- AI 基础设施回报必须按资产启用、利用率、收入、利润和现金流分层复查。
- 最新官方披露显示三家云厂商需求增长与高投入同时存在，回报验证仍是跨期过程。
- 折旧、云利润率和自由现金流是对订单与收入叙事的重要约束。

### 本课不能得出的结论

- 不能从分部或公司总量精确计算单个 AI 数据中心的 IRR。
- 不能把管理层“供不应求”表述当成经审计的容量利用率。
- 不能因一季自由现金流转负就断言长期回报失败，也不能因 RPO 高就断言成功。
- 本课不构成具体投资建议或收益承诺。
