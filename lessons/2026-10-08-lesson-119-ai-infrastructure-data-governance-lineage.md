# 第一百一十九课：AI 基础设施研究数据治理入门：来源链、口径字典、版本控制、重述和复核

## 基本信息

- 日期：2026-10-08。
- 核验截止：2026-10-08；公司事实使用截至该日可取得的最新相关定期报告。
- 主题：怎样让投后工作台中的每个数字都能回到原始披露，并让修改、重算和结论变化可复核。
- 学习目标：建立来源链、指标字典、原始口径与调整口径双轨、版本控制、重述处理、复核证据和权限分工。
- 适用对象：零基础学习者；本文不构成审计、会计、法律或证券投资意见。
- 核心来源：SEC EDGAR 与 Inline XBRL 指南、SEC 10-K 阅读公告、CoreWeave 2026 Q2 10-Q、Microsoft FY2026 10-K、Alphabet 2026 Q2 10-Q。

## 第一大板块：理论基础

### 1. 数据治理不是“把文件存整齐”

Data Governance，数据治理，是规定数据从哪里来、怎样定义、谁能修改、如何复核和何时失效。文件夹整齐只是表面，真正目标是让另一位研究者能够重做同一指标，并理解为什么本期结论与上期不同。

投后工作台至少有三类内容：

- 原始事实：财报中的金额、期间和文字披露；
- 派生计算：增长率、差异、覆盖倍数和情景结果；
- 分析判断：风险解释、触发状态和行动建议。

三类内容必须分栏。把判断写成事实，或把计算结果误称为公司披露，都会破坏证据链。

### 2. Source of Truth：确定原始真值入口

Source of Truth，权威来源，是某项事实应优先回到的原始文件。美国上市公司研究中，常见顺序是：

1. SEC 提交的 10-K、10-Q、8-K 及附件；
2. 公司投资者关系网站的同一原始公告；
3. 监管、交易所或标准制定机构文件；
4. 权威数据库的结构化转录；
5. 新闻、研究报告和社交媒体二手解释。

来源优先级不等于所有 SEC 文件都无误。SEC 明确说明，公司编写并提交 10-K，SEC 设定披露要求并审查，但不替公司为内容准确性背书；CEO 和 CFO 还承担相应认证责任。[S1] 因此研究者仍要做勾稽、口径和版本检查。

### 3. Data Lineage：给数字画一条回家路线

Data Lineage，数据血缘或来源链，记录一个指标从原始披露到最终工作台的全过程。最低字段包括：

| 字段 | 示例 |
| --- | --- |
| 公司与法律主体 | CoreWeave, Inc. 合并口径 |
| 表单与报告期 | 2026 Q2 Form 10-Q，截至 2026-06-30 |
| 提交日 | 2026-08-12 |
| 原始位置 | Note 5 Property and Equipment |
| 原始标签 | Property and equipment, net |
| 原始数值与单位 | 46,736，百万美元 |
| 计算公式 | 本期减上期，再除以上期 |
| 工作台名称 | PPE 净额同比或半年变化 |
| 版本与复核人 | v1.2，复核日期 |

只有网址没有页码、表名或标签，未来仍可能找不到原始数字。只有截图没有文本，也无法确认是否来自修订文件。

### 4. Metric Dictionary：先定义再计算

Metric Dictionary，指标字典，是所有指标的名称、定义、单位、期间、公式、包含项、排除项和来源优先级。比如“资本开支”可能指现金流量表购买物业设备、PPE additions、含租赁的资产增加、管理层 Non-GAAP 指标，四者不是一回事。

一条合格定义可以写成：

“现金资本开支：本期现金流量表中购买物业和设备的现金支出；不含通过融资租赁、OEM 融资或应付账款取得但本期未付现的资产；单位为百万美元；期间为年初至报告日。”

指标名称不能只写 Capex。必须附口径。

### 5. As Reported 与 Normalization 双轨

As Reported，报告口径，是公司按适用会计准则和披露格式发布的原始数字。Normalization，标准化调整，是研究者为可比性作出的调整，例如统一汇率、剔除一次性项目、把租赁本金加入资本开支或按相同期间年化。

正确做法是保留两列：

| 项目 | 报告口径 | 调整口径 | 调整理由 |
| --- | ---: | ---: | --- |
| 经营现金流 | 公司原值 | 调整后原值 | 列明移除或加入项目 |
| 资本开支 | 现金购买 PPE | 含非现金融资的资产增加 | 比较资产扩张 |
| 自由现金流 | CFO 减现金 Capex | 研究口径 FCF | 不冒充公司披露 |

标准化不是“修正公司”。它是研究目的下的另一个视角，必须保留原值和完整公式。

### 6. Period、Unit 与 Scope 三个最常见错误

任何数字先过三个检查：

- Period，期间：季度、半年、财年还是期末时点；
- Unit，单位：美元、百万美元、百分比、MW 还是股数；
- Scope，范围：合并公司、分部、项目、法律主体还是资产组。

例如上半年折旧不能直接与全年资本开支相减；期末 PPE 是时点余额，收入是期间流量；Google Cloud 分部利润不能直接除以 Alphabet 全部技术基础设施资产得到项目回报率。

### 7. Inline XBRL 有用，但标签不是经济含义本身

SEC 的 Inline XBRL 将机器可读标签嵌入可阅读文件，EDGAR Viewer 可在无需专门软件时查看标签。[S2] 它适合批量抓取、单位检查和期间对齐，但仍需阅读脚注。

公司扩展标签、维度成员、符号方向、单位缩放和同名指标的定义可能不同。机器抓到数字后，研究者应回到相关报表和注释确认。结构化数据提高效率，不会自动解决经济可比性。

### 8. Version Control：每次改变都留下前后版本

版本控制至少记录：

- 版本号和修改时间；
- 修改人、复核人；
- 修改字段；
- 原值、新值和理由；
- 使用的新来源；
- 受影响的公式、情景和结论。

若新财报发布，应建立新报告期版本，不要覆盖旧季度。若发现抄录错误，可以更正同一版本，但要保留更正记录。若公司提交 10-Q/A 或 10-K/A，应把它识别为来源版本变化。

### 9. Restatement、Revision 与 Estimate Change

Restatement，重述，通常指以前财务报表存在需要更正的错误并按规定重新列报。Revision，可译为修订，可能在后续文件中修正但严重程度和程序不同。Estimate Change，会计估计变更，则反映新信息，例如设备使用寿命变化，不一定说明过去数字错误。

研究工作台不能把三者都标成“公司改口”。处理步骤是：保存旧值、识别公司使用的正式术语、更新受影响期间、重算派生指标、说明结论是否变化。

### 10. Review Evidence：复核不是打勾

Review Evidence，复核证据，是证明复核人实际检查过数据和公式的记录。可以包括：

- 原始文件链接与定位；
- 三表勾稽或单位检查；
- 公式复算；
- 与上期异常变动比较；
- 对新扩展标签的解释；
- 复核意见和关闭日期。

仅在表格中勾选“已审核”不足以证明复核内容。对高风险指标，可实行制表人与复核人分离。

### 11. Materiality 与研究重要性

Materiality，会计重要性，取决于遗漏或错报是否可能影响报表使用者决策。研究工作台还需要“决策重要性”：某个金额对合并报表不重大，却可能改变单个项目是否继续。

因此，公司没有记录重大错报，不代表项目级数据足以支持所有研究结论；内部控制缺陷也不等于已发生财务造假。必须保持事实、风险和推理边界。

## 第二大板块：实时背景与市场传导

### SEC：表单、结构化数据与责任边界

已确认事实：SEC 的 EDGAR 研究指南说明，10-K 提供经审计年度财务报表、风险因素和 MD&A；10-Q 提供未经审计季度财务报表、风险更新和 MD&A；8-K 用于定期报告之间的重要事件。SEC 也提供 Inline XBRL Viewer，结构化信息可被程序读取。[S2][S3]

SEC 的 10-K 阅读公告同时强调，公司编制并提交文件，CEO 与 CFO 对 10-K 作认证；SEC 规定披露框架并审查，但不编写报告，也不对内容准确性作保证。[S1]

分析推理：工作台的来源状态至少应包括“经审计年度”“未经审计季度”“当前事件”和“研究者计算”。一条 8-K 业务更新不能自动替代后续 10-Q 的完整会计口径。

仍需观察：公司是否提交修订文件、标签是否变化、后续 10-Q 或 10-K 是否更新前期估计。

### CoreWeave：控制缺陷要求更强的复核，不等于数据无效

已确认事实：CoreWeave 在 2026 Q2 10-Q 中披露，CEO 与 CFO 认为截至 2026-06-30 的披露控制和程序在合理保证水平上无效，原因是财务报告内部控制存在重大缺陷。披露涉及 IT 一般控制、职责分离和具备适当经验人员数量等问题；公司同时说明这些缺陷未导致其财务报表出现重大错报，并披露正在整改。[S4]

同一报告披露 PPE 净额 467.36 亿美元、在建工程 119.18 亿美元、上半年现金支付 PPE 141 亿美元，以及与 PPE 增加有关的负债和 OEM 融资等非现金活动 97.96 亿美元。[S4]

分析推理：重大缺陷提高数据产生过程的风险，研究者应加强来源定位、跨表勾稽和后续修订监控；但不能把“控制无效”直接写成“所有数字错误”或“公司欺诈”。

仍需观察：整改是否经过足够期间的运行测试、后续管理层结论、审计师要求以及是否出现修订或重述。

### Microsoft：RPO 本身包含判断

已确认事实：Microsoft FY2026 10-K 说明，Remaining Performance Obligations 是预计未来确认、但控制尚未转移给客户的收入。估计总对价和分配给 RPO 的收入可能涉及重大判断，包括可变对价和承诺重新谈判。[S5]

分析推理：工作台不能把 RPO 当成无风险现金。指标字典应记录其定义、预计确认期限、可变对价、取消或重谈风险，并与递延收入、账单和现金收款区分。

仍需观察：后续确认节奏、客户用量、合同修改和口径变更。不同公司的 RPO 定义与业务模式不必完全可比。

### Alphabet：分部结果含分摊，资产口径更广

已确认事实：Alphabet 2026 Q2 10-Q 披露，Google Services 和 Google Cloud 的成本与费用包含直接成本和分摊成本，包括技术基础设施与办公设施使用成本。公司还披露 2026-06-30 尚未投入使用资产 1,228.14 亿美元，物业与设备净额 3,212.12 亿美元。[S6]

分析推理：Google Cloud 分部利润已经包含分摊，但公开文件没有给出每个项目的资产和成本分配表。用 Alphabet 全部 PPE 计算 Cloud 项目 ROIC 会发生范围错配。

仍需观察：分摊方法变化、资产投运、折旧和分部披露更新。外部研究只能建立代理链条。

### 数据治理如何改变市场判断

原始文件发布
-> 来源链记录表单、期间、单位与范围
-> 指标字典决定报告口径和调整口径
-> 自动抓取与人工脚注复核
-> 差异、情景和触发器重算
-> 结论版本更新并保留旧版本
-> 后续修订、重述或控制披露再核验

如果跳过中间步骤，同一条新闻可能在收入、RPO 和现金预测中被重复计算，或把非现金资产增加误当作本期现金流出。

## 政治、制度和规则视角

财务报告治理来自证券法、SEC 表单要求、Sarbanes-Oxley 内部控制与认证、会计准则以及审计制度。研究者不是审计师，但应理解这些制度决定了信息的责任人、更新频率和保证程度。

结构化数据政策提高机器可读性，也带来标签治理问题。2026 年 SEC 仍持续发布 EDGAR 和 XBRL 技术资料，并由数据标准部门处理标签、分类标准和数据质量问题。[S2] 自动化课程或工作台应保存原始文件和抓取时间，避免网页更新后无法复现。

政策、监管或出口管制可能同时改变项目经济和披露要求。工作台应把“经济影响来源”与“数据来源”分开记录。

## 案例拆解

研究者想在工作台放入“CoreWeave 上半年基础设施投入”。他找到三个数字：

- 现金支付 PPE：141 亿美元；
- 与 PPE 增加有关的负债及 OEM 融资等非现金活动：97.96 亿美元；
- 期末 PPE 净额：467.36 亿美元。

错误做法是直接把三者相加为 706.32 亿美元，并命名“总资本开支”。PPE 净额是期末存量，包含以前期间资产并扣除了累计折旧；现金支付和非现金活动是期间流量，且需要检查是否存在重分类或重叠。

正确来源链分别记录三项，再根据目的建立指标：

| 指标 | 公式或取值 | 用途 |
| --- | --- | --- |
| 现金资本投入 | 141 亿美元 | 观察本期现金需求 |
| 非现金资产融资线索 | 97.96 亿美元，保留原披露名称 | 观察未通过现金支付形成的资产与负债 |
| 期末资产基础 | PPE 净额 467.36 亿美元 | 观察资产存量 |
| 资产扩张 | 本期末 PPE 净额减上期末 PPE 净额 | 观察余额变化，不等于现金 Capex |

然后增加数据质量标记：来源为 10-Q、未经审计季度、报告期截至 2026-06-30；公司披露重大控制缺陷仍存在，但未导致已识别重大错报。结论应是“提高复核和后续监控强度”，而不是删除全部数据或断言失实。

## 个人情境连接

个人可以给每个关键指标增加八列：原始名称、原始值、单位、期间、范围、链接、公式、最后复核日。每次更新复制新版本，不覆盖上一期。

使用自动抓取时，先抽查单位和符号。看到程序给出的增长率异常，先查标签、期间和合并范围，再解释业务。自动化负责减少抄录，不能替代判断。

## 结论边界

1. SEC 文件是优先原始来源，但 SEC 不替公司保证披露准确。
2. Inline XBRL 提高机器读取效率，不自动保证经济口径可比。
3. 报告口径与调整口径必须双轨保留，研究调整不能冒充公司披露。
4. 重大控制缺陷表示错报风险，不等于已发生重大错报或欺诈。
5. 重述、修订和估计变更有不同含义，必须使用公司正式表述。
6. 公司级、分部级和项目级范围不能混算；未知应明确保留。

- 建议案例：围绕一个投运延迟且追加融资的项目，分别形成继续、条件继续、暂停、缩减和退出方案。
- 必须解释：Decision Memo、Red Team、Conditional Approval、Decision Right、Escalation、Action Log、Closed-loop Review、Post-mortem。
- 开始前必须联网核验：最新公司项目进度、资本承诺、融资、风险因素、控制程序和重大事件披露。
